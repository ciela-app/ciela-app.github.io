Current Release v0.9.0 – v0.9.10 · July–Aug 2026

Rebuilt.

The entire desktop UI was redesigned from scratch — new navigation shell, rebuilt Insights, History, Cleaned, Settings, and Connect panels. Follow-on releases rerouted Gmail through IMAP, restored the 2-column inbox layout, added retroactive re-classification so Unknown senders resolve automatically on every scan, sharpened the classifier across nine categories, made the Outlook sign-in recovery buttons actually work, hardened the classifier engine with RFC 3834/2369 header detection and a full correctness pass, fixed three production IMAP bugs found in first real-world testing, fixed a provider-specific banner being shown to the wrong users and added a single-instance guard, fixed a Smart Purge Tray loop that caused the same senders to reappear after every rescan, and in v0.9.10 fixed the underlying root cause — Ciela's local caches now shrink when mail is trashed.

0.9.10

2026-08-02

Bug fix. Ciela's local caches now shrink when mail is trashed — eliminating the phantom sender loop and inflated Dashboard counts permanently.

  • Trash cache consistency. v0.9.9 removed the phantom sender row after trashing. This release removes the phantom message rows. Every trash path now deletes local message rows at trash time, so a rescan can no longer find mail that Ciela already moved to Trash. Dashboard totals reflect reality; the Smart Purge Tray loop is gone at the root cause level.
  • Undo is more reliable. The undo path now re-fetches message metadata directly from your email provider after restoring, so Ciela's local view matches what the provider actually sees — not a cached state that may have drifted.
Technical notes
  • Root cause: no trash path deleted from the local messages table; incremental rescans use INSERT OR IGNORE and never clear them — so trashed mail's rows persisted indefinitely
  • Fix: reconcile_after_trash shared helper called by all trash paths (sync trash_sender, background worker, trash_category, rules_exec, triage); runs record_trash_op + chunked DELETE FROM messages + remove_sender in one transaction
  • Worker sourced from durable job_items WHERE status='DONE' — not in-memory trashed_ids — so resumed jobs reconcile correctly even when the prior execution already trashed the mail
  • complete_job reordered to run after cleanup; cleanup failure leaves job RUNNING so the startup sweep heals any crash mid-reconcile
  • Schema v28 → v29: ALTER TABLE trash_ops ADD COLUMN job_id TEXT (nullable; migration runs automatically on first launch)
  • 499 frontend / 757 Rust tests

0.9.9

2026-07-25

Bug fix. After clicking "Trash all" in the Smart Purge Tray, the same senders no longer reappear on the next rescan.

  • Smart Purge Tray loop fixed. Clicking "Trash all" moved emails to Trash at the provider level correctly — but the background worker was not removing the sender row from Ciela's local database. On the next rescan, the same senders would be matched against their existing trash history and re-appear in the tray. Sender rows are now cleaned up immediately after trashing, so the loop is gone.
Technical notes
  • Root cause: worker.rs execute_job completion path called record_trash_op but not remove_sender — the only trash path in the codebase that did not call both
  • Fix: extracted complete_clean_job helper that calls both in sequence; same accepted atomicity trade-off as the synchronous trash_sender path
  • 499 frontend / 738 Rust tests

2026-07-24

Bug fixes. An Outlook-specific popup was appearing for Gmail and IMAP users. Ciela now prevents two instances from running at the same time.

  • Outlook banner shown to wrong users. After a scan, Gmail and IMAP users were seeing a popup that said "Let Outlook handle this automatically?" and an "Outlook Filters" section in Settings. Both are Outlook-only features — they now only appear when an Outlook account is active.
  • Single-instance guard. Ciela now prevents two copies from running simultaneously. If you have two installations on disk, launching either one will focus the existing window rather than opening a second instance that could cause unpredictable behaviour.
Technical notes
  • get_provider_rule_suggestions backend command now early-returns empty for non-Outlook sessions
  • App.tsx: provider check added before rendering OutlookRuleBanner
  • SettingsView: ProviderRulesSection gated to Outlook accounts only; activeAccountId threaded from InboxView
  • tauri-plugin-single-instance added; second launch focuses existing window and exits
  • 499 frontend / 738 Rust tests

0.9.7

2026-07-21

IMAP hardening. Three production bugs fixed from first real-world IMAP testing: scans jumping from ~8% to done, trash silently doing nothing, and an undo error leaving the wrong folder selected.

  • Full inbox scan. Ciela now scans every message in an IMAP mailbox. A silent 10,000-message cap was causing the progress bar to jump from ~8% to 100% on any inbox larger than 10K messages.
  • Gmail IMAP trash folder fix. Messages trashed via Gmail's IMAP interface were going to Trash instead of [Gmail]/Trash — silently vanishing from Ciela's view without landing in the real trash. Non-English Gmail accounts (e.g. [Google Mail]/Trash) are handled via RFC 6154 server-advertised folder detection.
  • Trash no longer silently fails. A stale IMAP session after a long scan caused trash operations to succeed with zero results and no error toast. The failure reason is now shown in the notification.
  • Undo reliability. If an undo (untrash) operation failed mid-way, the IMAP connection was left pointing at Trash. The next trash command would then search Trash instead of the inbox and return nothing. Fixed by always restoring INBOX even on error.
  • Data integrity. Ciela's local DB was removing a sender's record even when zero messages were actually trashed — e.g. if the sender had already cleaned up their own messages. The sender record is now only removed when at least one message was confirmed moved.
  • IMAP scan restart notice. IMAP users who close and reopen Ciela mid-scan now see accurate messaging — IMAP doesn't yet support mid-scan resume, so the scan restarts from the beginning.
Technical notes
  • Removed 10K UID cap (MAX_UIDS); UID SEARCH ALL uses a dedicated 120s timeout for large inboxes
  • batch_untrash_messages: operations wrapped in inner block; INBOX always restored on error (contaminated-session fix)
  • batch_get_messages fetch failures now surface as failed_ids + last_error, triggering the error toast
  • Gmail IMAP added to provider slug table with [Gmail]/Trash; RFC 6154 LIST \Trash special-use detection added as fallback
  • remove_sender gated on trashed > 0 in all three callers
  • Trash observability: start/page/done info logs in trash_sender_inner
  • Council of Elrond reviewed twice — both sessions closed
  • 737 Rust tests

0.9.6

2026-07-16

Classifier hardening. RFC 3834/2369 header detection, single-pass scan, chain ordering bug fixes, and a full correctness pass across the classifier layer.

  • RFC 3834 and RFC 2369 header detection (POMPC C4). Auto-Submitted and List-Id headers are now read by the Gmail, Outlook, and IMAP providers. Mailing list traffic and auto-generated emails are classified at High confidence before falling through to keyword matching — this reduces Unknown and misclassification for bulk senders that use standard RFC headers.
  • Single-pass header scan (POMPC C5). Replaced three separate passes over message headers with one. Benchmark improvement of ~4% on large scans.
  • Chain ordering bugs fixed (CS-1). Jobs domain check was firing after Finance keywords (Jobs senders were landing in Finance). ActiveMarketing domain check was firing after DeadMarketing keywords (dead marketing senders were landing in ActiveMarketing). Both chains are now in the correct order.
  • Financial senders subdomain fix (CS-2). The Tier 1/2 financial domain check now uses a suffix-walk, so subdomains like secure.wellsfargo.com correctly match.
  • Gmail metadataHeaders expansion. List-Id, Auto-Submitted, Precedence, and X-Mailer are now fetched in Gmail batch requests. RFC 3834/2369 signals now fire for Gmail users.
Technical notes
  • POMPC C4–C7 refactor; scan_headers_once replaces three separate header passes
  • scan_headers_once confidence distribution log added (C6); classifier architecture doc updated (C7)
  • CS-3: 3 redundant/invalid keyword entries removed; CS-4: full chain documentation + 11 new tests
  • 0 clippy warnings across the full codebase
  • 735 Rust tests · 499 frontend tests

0.8.0

2026-06-26

Bug fix release. Trash History and Undo restored, blank inbox on first scan fixed, OAuth refresh token rotation fixed, Outlook rules cleanup on disconnect.

  • Trash History and Undo restored. Both were silently broken since v0.7.0. Emails moved to trash correctly, but the record was never written — so Trash History was always empty and Undo did nothing. Fixed: the undo record is now written immediately after each clean operation completes.
  • Blank inbox on first scan fixed. After a fresh install, the first scan completed but showed zero senders. Caused by a race between the scan finishing and the UI reading the results. Scan now returns results directly — one round-trip, race eliminated.
  • OAuth refresh token fix. When Gmail or Outlook refreshed an access token mid-session, any rotated refresh token was silently dropped. On app restart, the stale token would fail, forcing you to reconnect. The new refresh token is now saved to the system keychain every time.
  • Outlook rules cleanup on disconnect. Ciela-created Outlook inbox rules now delete automatically when you disconnect. Previously they stayed in your Microsoft account indefinitely after uninstalling.
  • Outlook rules panel always visible. The "Your Outlook Filters" section in Settings was hidden when no rule suggestions existed, making active rules unmanageable. It now appears whenever rules are present.
  • Post-scan Outlook filter suggestions. After scanning, if Outlook senders have been trashed two or more times with no active rule, the top candidate surfaces in a banner. One tap creates the rule; dismiss to skip for the session.

0.7.0

2026-06-22

Cleaning jobs now run in the background — queue what you want gone, close the window, and come back to a finished inbox. Ciela also groups emails by company, protects your financial accounts, and gives new users a guided start. New icon.

  • Clean and walk away. Cleaning jobs now run in the background. Queue up what you want Ciela to trash — a sender, a category, or an entire brand group — then close the window. Ciela keeps working, shown in your system tray, and sends a notification when it's done. You can queue several operations at once; they run in order.   • Start Here. New users now see an orientation screen when they first connect — a plain-language explanation of what Ciela is about to do, with a clear button to begin. Less guesswork on first install.
  • Confidence-graded triage. The triage checklist now shows how confident Ciela is in each recommendation — so you can focus your attention on the suggestions that need a second look, and trust the ones that are clearly right.
  • Better sender recognition. Ciela uses DMARC authentication data to confirm who is actually sending your email — catching senders who use different display names or domains to obscure their identity.
  • New icon. A crescent moon on a night sky — across the app icon, taskbar, installer, and website favicon.
