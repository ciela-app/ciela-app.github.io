0.2.15

2026-05-06
Added
  • Virtual scrolling on the sender list — the Senders view now renders only the rows visible in the viewport using @tanstack/react-virtual. For large inboxes (8,000+ senders) this eliminates the DOM cost of mounting thousands of nodes at once.
    • Items are positioned absolutely with transform: translateY(…px) so the browser can composite them on the GPU without triggering layout.

Infrastructure

0.2.1

2026-04-29
Added
  • Incremental scan — after the first scan, subsequent scans fetch only emails received since the last scan date (after:{timestamp} Gmail query). New senders are merged into the existing database (thread counts accumulate); the complete updated list is returned to the UI. First-time users still get a full scan automatically.
  • Gmail batch API — each page of message IDs is now fetched in batches of up to 100 using the https://www.googleapis.com/batch/gmail/v1 endpoint, reducing the number of HTTP round-trips by up to 100x. Individual failures within a batch are skipped without aborting the scan. HTTP 429 / 503 responses retry with exponential backoff (500ms → 30s, up to 5 retries).
  • Scan mode indicator — the scanning screen shows "Checking for new mail…" for incremental scans and "Scanning your inbox…" for full scans.
Fixed
  • Rate-limit token accounting in batch fetch — batch_get_messages now consumes one rate-limiter token per message (not one per batch of 100), matching Gmail's actual quota cost and preventing 403 errors on the second page of results.
  • Retry-with-backoff on list_messages — up to 3 retries (5 s / 10 s / 20 s) so a transient 429 on a paginated scan heals silently without surfacing an error to the user.
  • Retry-with-backoff on all API calls — execute() retries 429 / 503 responses up to 5 times with exponential backoff (2 s → 60 s cap).
  • DB corruption recovery on startup — db::open() now catches corrupted or key-mismatched SQLCipher files, silently wipes and recreates the database instead of panicking; prevents a crash-on-startup loop after a hot-reload mid-write.
  • Rate limiter ceiling — bumped from 20 req/s to 40 req/s, giving headroom below Gmail's hard 50 msg/s quota ceiling.
  • Milestone toasts removed — scan screen no longer shows "N senders found!" toasts; finding junk is not an achievement worth celebrating.
  • Tip rotation slowed — rotating tips on the scan screen now cycle every 15 s (was 8 s) to accommodate slower readers.

Fixed
  • Infinite rescan loop on stale checkpoint (bug fix) — when a scan was interrupted, the saved page token could expire before the next session. Gmail returned HTTP 400 on the first list_messages call, causing an early return that bypassed scan_state::clear. The stale checkpoint stayed on disk, and every subsequent rescan hit the same error in a loop. Fix: clear the checkpoint in scan_inbox whenever scan_inbox_inner returns an error, so the next rescan starts from page 1.

0.1.1

2026-04-28
Security
  • OAuth CSRF protection (C-1) — added random state parameter to the auth URL; listen_for_code now verifies the returned value before accepting the authorization code
  • Port TOCTOU fix (C-2) — the TCP listener is now held open from bind time through the OAuth callback; eliminated the race window where a competing process could steal the port between bind/drop/rebind
  • Content Security Policy (H-1) — added strict CSP to the WebView (default-src 'self', no inline scripts, connect-src limited to IPC and https://ipc.localhost)
  • Access token no longer returned to JavaScript (H-2) — connect_gmail now returns () instead of the live token; the token lives only in Rust state
  • Shell plugin removed (L-6) — shell:default capability removed from the WebView; browser is opened via open::that() on the Rust side only
  • Gmail query injection hardened (M-1) — sender_email is validated against a strict format check and wrapped in quotes in the Gmail query string
  • Date filter validated server-side (M-2) — older_than_days must be one of {30, 90, 180, 365, 1825}; all other values are rejected before reaching the API
  • Unsubscribe URL validation (M-3) — extracted URLs are validated with url::Url::parse; only https scheme and public internet hosts are accepted; RFC-1918 and loopback hosts are rejected
  • Internal errors no longer forwarded to frontend (L-3) — Gmail API errors are logged server-side with log::error! and replaced with opaque user-friendly messages
Fixed
  • Shared rate limiter (H-7) — rate limiter moved to AppStateInner and shared across all GmailClient instances; concurrent scan + trash no longer doubles the effective request rate
  • Token expiry checked in is_connected (H-3a) — expired access tokens are now treated as disconnected
  • Refreshed token written back to AppState (H-3b) — after scan_inbox and trash_sender complete, the current (possibly refreshed) access token is written back to AppStateInner
  • OAuth timeout (H-4) — listen_for_code is now wrapped in tokio::time::timeout(120s); closing the browser tab without signing in returns a clear error instead of hanging forever
  • Duplicate Authorization header on 401 retry (H-5) — the stale Authorization header is stripped from the cloned request before the refreshed token is added
  • Checkpoint saved after page processes (H-6) — scan_state::save now runs after each page's buffer_unordered collect completes; a mid-page crash no longer silently skips up to 500 messages on resume
  • parse_from panic on malformed headers (M-4) — replaced rfind('<') with find('<') then a forward search for >, guaranteeing end > start on all inputs
  • Arc::try_unwrap discarding scan results (M-5) — replaced with sender_map.lock().await; lock contention can no longer silently discard minutes of API results
  • Scan counter overflow in release (M-6) — scanned counter now uses saturating_add so overflow in a release build can't abort the process
  • Stale senders_found in progress events (M-7) — senders_found is now read from inside the same lock acquisition as category_counts, ensuring both values are from the same snapshot
  • Individual trash failures reported (M-8) — failed trash calls are counted and emitted as a trash_error event instead of being silently ignored
  • Atomic checkpoint writes (L-1) — checkpoint is now written to a .tmp file then renamed into place; a crash mid-write no longer produces partial JSON that causes silent checkpoint loss
  • disconnect clears expires_at (L-2) — stale expiry timestamp is cleared on disconnect
  • has_bulk_headers Precedence check (C-3) — fixed dead code where "precedence: bulk" was checked against header names (which never contain colons+values); now checks name == "precedence" && value.contains("bulk") correctly
  • Deterministic category tie-breaking (L-4) — tied vote counts now resolve by a fixed priority order instead of HashMap iteration order; same sender always classifies the same way across runs
  • Trash streamed page-by-page (L-5) — trash_sender no longer accumulates all message IDs in memory before starting; each page is trashed as it is fetched
  • Dead dependencies removed (M-9) — rusqlite, aes-gcm, and the db module removed; these were unused in v1 and added unnecessary attack surface and binary size
Tests
